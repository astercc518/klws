# wadist V1.0 架构与运维交接文档

> 本文记录 2026-06-26 完成的「全栈 Go(htmx)→ 前后端分离 SaaS」重构成果,面向接手的研发/运维。
> 业务与底层引擎全景见 [PLATFORM-OVERVIEW-zh.md](PLATFORM-OVERVIEW-zh.md);本文只覆盖**新增的 API 层、前端、部署与运维**。

---

## 0. 一句话现状

底层五大引擎(`billing` 计费 / `dispatch` 分发 / `store` RLS / `sendgate` 健康 / `cluster` 发信)**一行未改**;在其之上新增了:
- **Gin JSON API**(`internal/api`)替代原 `internal/console` 的 html/template 视图层;
- **Next.js 前端**(`frontend/`):客户控制台 + 超管后台;
- **同源部署**于 `klws.cc`,并以 **systemd** 守护常驻。

所有管理能力都通过 API 层 + `store.SystemPool()`(BYPASSRLS)/ 既有 repo 释放,**不碰红线引擎逻辑**。

## 1. 顶层拓扑

```
浏览器 ──HTTPS──▶ Cloudflare(边缘证书=小绿锁)
                     │
                     ▼  (HTTP/HTTPS,源站 Cloudflare Origin 证书)
        wadist-proxy 容器 (nginx, host 网络, :80/:443)
           ├─ location /api/  ─▶ 127.0.0.1:8080  klws-backend  (Gin API, systemd)
           └─ location /      ─▶ 127.0.0.1:3000  klws-frontend (Next.js standalone, systemd)

        共享基础设施(Docker 容器):
           wadist-pg    postgres:16   host:5433 → 5432
           wadist-redis redis:7       host:6379
```

**同源**:前端构建期把 `NEXT_PUBLIC_API_BASE_URL=/api/v1`(相对路径)烤进客户端包,浏览器请求天然同源命中 `klws.cc/api/...` → 无需 CORS。

## 2. 后端 API(`internal/api`)

### 2.1 文件结构
| 文件 | 职责 |
|------|------|
| `router.go` | 路由树、JSON 信封 `{code,data,message}`、`cors`、`requireAuth`/`requireRole` 中间件 |
| `server.go` | HTTP 生命周期(Start/Addr/Shutdown) |
| `auth.go` | 登录/登出/me |
| `tenant.go` | 客户钱包/信息/大盘(RLS) |
| `campaign.go` | 客户群发提交/列表(移植自 `console.createCampaign`) |
| `admin_api.go` | 超管「上帝视角」:大盘/租户/IAM/财务/资源池/全局任务 |
| `sales_api.go` | 销售视角:仅本人名下客户 |

### 2.2 鉴权模型(零重写)
- 登录:复用 `console.UserRepo.Authenticate`(argon2id)→ `console.SessionStore`(Redis)建会话 → 返回 **Bearer Token**(即 `console.SignCookie` 产出的 `sid.hmac`,与旧 Cookie 同源同密钥)。
- 携带:前端 `Authorization: Bearer <token>`;中间件用 `console.VerifyCookie` + `SessionStore.Get` 验证。
- 角色:`requireRole(admin|sales|customer)`;客户数据走 `mgr.WithTenant()`(RLS),管理数据走 `mgr.SystemPool()`(BYPASSRLS)。
- **Token 模式天然免疫 CSRF**,旧的双提交 CSRF 已废弃。

### 2.3 接口清单(均在 `/api/v1` 下)
**Auth**(公开/鉴权):`POST /auth/login` · `POST /auth/logout` · `GET /auth/me`
**Customer**(`requireRole customer`,RLS):`GET /tenant/wallet` · `GET /tenant/stats` · `GET /tenant/info` · `POST /campaigns` · `GET /campaigns`
**Sales**(`requireRole sales`,先过 `salesOwns`):`GET /sales/customers` · `GET /sales/customers/:id` · `POST /sales/customers/:id/pricing`
**Admin**(`requireRole admin`):
- `GET /admin/stats`
- `GET /admin/tenants` · `POST /admin/tenants` · `GET /admin/users` · `POST /admin/users` · `POST /admin/sales/:id/assign`
- `POST /admin/finance/topup` · `POST /admin/finance/pricing` · `GET /admin/finance/ledger`
- `GET /admin/resources/proxies` · `POST /admin/resources/proxies` · `GET /admin/resources/devices` · `POST /admin/resources/devices`
- `GET /admin/campaigns` · `POST /admin/campaigns/:id/stop`

## 3. 前端(`frontend/`)

- 栈:**Next.js 16 / React 19 / Tailwind v4 / shadcn(base-nova, neutral 单色)/ Tremor**;App Router;`output: standalone`。
- 视觉:黑白「遥测仪表盘」风;Geist Mono 跑数字;客户控制台白底,超管后台侧栏反色(上帝视角)。
- 路由:`/login` · `/`(客户大盘,route group `(dashboard)`)· `/admin`、`/admin/tenants`、`/admin/resources`、`/admin/devices`、`/admin/audit`。
- 网络层:`lib/api.ts` —— 统一解析信封、自动带 Bearer、**全局拦截 401 → 跳 `/login`**;`login()/logout()` 便捷封装。
- 关键交互:客户「新建群发」Dialog;超管「充值/设单价」二次确认 Dialog;代理/设备**批量粘贴导入** Textarea;风控页「强制终止」(接 `/admin/campaigns/:id/stop`,置 `paused`)。

## 4. 部署与运维(单机生产)

> **现状(2026-06-26 切换后)**:线上已由 **docker-compose** 守护(见 §4.6 与 [deploy/README.md §8](../deploy/README.md))。下面的 §4.1 systemd 方案**已弃用、`disable` 停用,仅作回滚保留**(产物仍在 `/opt/klws/`)。切换时用 `docker-compose.adopt.yml` 复用了原 PG 数据卷,数据零迁移;切换前整库 `pg_dump` 备份已留存。

### 4.1 systemd 守护(已弃用,保留回滚)
| 服务 | 单元 | ExecStart | 端口 |
|------|------|-----------|------|
| `klws-backend` | `/etc/systemd/system/klws-backend.service` | `/opt/klws/bin/klws-console` | 8080 |
| `klws-frontend` | `/etc/systemd/system/klws-frontend.service` | `/usr/bin/node /opt/klws/frontend/server.js` | 3000 |

均 `Restart=always` / `RestartSec=5`;已实测 `kill -9` 后 ~5s 自愈。

### 4.2 产物与配置落位(脱离 /tmp)
- 后端二进制:`/opt/klws/bin/klws-console`
- 前端 standalone:`/opt/klws/frontend/`(`server.js` + `.next/static` + `public`)
- 环境变量(**600**):`/etc/klws/backend.env`(9 个 `WADIST_*`:3 DSN + Redis + 主密钥 + 盲索引 + 会话密钥 + Addr + Cookie)、`/etc/klws/frontend.env`

### 4.3 发布新版本(改代码后)
```bash
# 后端
cd /var/klwa && go build -o /opt/klws/bin/klws-console ./cmd/console
systemctl restart klws-backend

# 前端
cd /var/klwa/frontend && NEXT_PUBLIC_API_BASE_URL=/api/v1 npm run build
cp -a .next/standalone/. /opt/klws/frontend/
cp -a .next/static /opt/klws/frontend/.next/   &&  cp -a public /opt/klws/frontend/
systemctl restart klws-frontend
```

### 4.4 演示/初始数据
`cmd/seed`(幂等)注入:租户 Demo Tenant、钱包 $10,000、US 单价 $0.05、Demo Tenant 归属销售,及三个账号:
- 客户 `demo@wadist.local / demo12345` → `/dashboard`
- 超管 `admin@wadist.local / admin12345` → `/admin`
- 销售 `sales@wadist.local / sales12345` → `/sales`

```bash
# A) 源码方式(host 上,DSN 用真实库)
cd /var/klwa && WADIST_POSTGRES_DSN='<同 backend.env>' go run ./cmd/seed

# B) compose 镜像内方式(连内网 postgres)——backend 镜像内含 /seed 二进制。
#    ⚠️ 必须用 --entrypoint /seed 覆盖,否则会被跑成 `/console /seed`(启动服务器而非 seed)。
docker compose -f docker-compose.prod.yml -f docker-compose.adopt.yml \
  run --rm --entrypoint /seed backend
```

## 5. ⚠️ 已知风险与技术债(交接重点)

1. **重启自愈链路已加固 ✅(原最高优先级风险已修复)**:`wadist-proxy` 的 `nginx.conf` + Cloudflare Origin 证书已从 `/tmp` 迁到 **`/etc/klws/proxy/`**(`klws.cc.key` 600),容器以 `--restart=always` 重建;`wadist-pg`/`wadist-redis` 也由 `restart=no` 改为 `always`;`docker.service` 已 `enabled`。配合 systemd 的 `klws-backend`/`klws-frontend`,**整机重启后全链路自动恢复**。改代理配置的方式:编辑 `/etc/klws/proxy/nginx.conf` 后 `docker restart wadist-proxy`。
2. **真实发信未通**:要让消息真正发出,需启动 `cmd/wadist` 发信节点并扫码接入在线 WA 账号;当前提交群发只会建 `running` 活动并入队,逐条预扣费(`billing.Hold`)发生在节点处理时。
3. **几处务实口径(非 bug,需知会)**:超管充值**只加不减**(billing 引擎无借记);「队列积压」用 `pending` 收件人数近似(非 asynq 真实深度);「强制终止」=置 `paused`;「接入新账号」二维码为**预留位**(实时配对是节点侧 whatsmeow 流程);客户大盘趋势图为**示例数据**(无时序端点)。
4. **明文 PII 列收缩**等底层技术债见 PLATFORM-OVERVIEW §4(本次重构未触碰)。
