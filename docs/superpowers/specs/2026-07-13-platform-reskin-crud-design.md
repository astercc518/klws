# KLWA 全平台管理系统重塑(换皮 + CRUD 补缺)设计

日期:2026-07-13
状态:已获用户批准(头脑风暴八问定案)

## 1. 背景与目标

现有管理后台经 SP1–SP8 已覆盖客户中心、财务流水、账单统计、审计、发送记录、佣金、模拟登录等能力,数据面刚完成 whatsmeow → Evolution API 全量切换(E0–E6)。用户需要一套"高颜值多功能的 CRUD 管理系统",经逐问澄清,需求定型为:

- **路线 A(重塑现有后台)**:保留全部已验证的后端接口与页面骨架,不推倒重来。
- **视觉**:模仿 WhatsApp 官方主题的高质感设计;完整亮/暗双主题;中/英双语切换。
- **范围**:全平台统一换脸——`/admin` + 客户 `/dashboard` + 销售 `/sales` + 登录/注册等公共页。
- **功能补缺(用户确认的四大块)**:账号/实例运维、风控与发送监控、历史趋势与报表、现有表格操作效率。
- **顺序**:基建先行全站换脸,再逐模块精修补功能。
- **库存分支**:`feat/contacts-audience`(联系人库,已终审 READY)先合入 main 纳入换皮。
- **驱动力**:对外演示卖相与日常运营效率并重。

## 2. 总体架构原则

- 技术栈不变:Next.js 16 + React 19 + Tailwind 4 + shadcn + Base UI + Tremor + next-themes。
- 五大引擎(billing/dispatch/store/sendgate/cluster)业务逻辑不改;新增后端仅限 `internal/api` 只读/管理接口与独立的指标快照存储。
- 每期独立走 spec → plan → 实现,可用即可上线,互不阻塞。

## 3. Phase 0:库存清理(前置)

1. 合并 `feat/contacts-audience` 进 main(拖越久冲突越多)。
2. 将 main 本地领先 origin 的提交推送,给换皮一个干净可回溯的起点。

## 4. Phase 1:基建(全站换脸地基)

### 4.1 主题系统
- Tailwind 4 `@theme` token 化:WhatsApp 色板定义为语义 token(`--primary` 绿 `#25D366`、`--primary-deep` 深青 `#128C7E`、暗色底 `#111B21` 墨蓝系、surface/chat-bubble 等),亮暗两套值。
- 所有页面只消费 token;`next-themes`(已装)负责亮暗切换。

### 4.2 双语方案
- **不用 URL 前缀路由**(`/en/...` 会破坏现有路由与书签)。
- React Context + 两份 JSON 字典(`zh.json` / `en.json`),locale 存 cookie,服务端 async 根布局经 `getLocale()` 读取(cookie 优先→`Accept-Language`→默认 zh),SSR 首屏即正确语言,无水合闪烁;切换写 cookie + `router.refresh()`。(采纳自 `feat/app-i18n-ssr` 分支已实现机制,原 localStorage 方案有英文浏览器首屏闪烁问题。)登录后应用无 SEO 需求,零路由改动、零新依赖。

### 4.3 布局壳
- 统一侧边栏(可折叠,沿用 SP8 OKCC 式分组导航)+ 顶栏(全局搜索、语言切换、主题切换、身份/模拟登录标识)。

### 4.4 组件底座
- `ProDataTable` 一次性升级:批量选择+批量操作条、列显隐自定义、高级筛选抽屉、`/` 快捷键聚焦搜索。全部列表页共同受益,即"表格操作效率"缺口的总解。
- Tremor 图表统一接主题 token(亮暗自适应)。

## 6. 关键依赖与风险

1. **实例运维 UI 依赖 Evolution 真机联调**:真机验证目前为 0(QR 字段名、V3 状态码等未确认)。扫码接入向导正是全量重扫码与真机 runbook 的抓手——模块②排 Phase 2 第一个做,做完直接用它跑真机验证。
2. **历史趋势需新存储**:指标快照表 + 采样任务,是本次唯一后端结构性新增;只读采样现有表,不触碰引擎业务逻辑。
3. **风控旋钮**:第一版只读可视化;"可调节"涉及引擎配置写入,单独立项评审后再开。

## 7. 分期交付

- **P0** 合分支 + 推送(前置)
- **P1** 主题 / 双语 / 布局壳 / 表格底座 → 全站换脸上线(最快见效)
- **P2** 实例运维 + 扫码向导(顺带完成 Evolution 真机验证)
- **P3** 风控监控看板 + 报表中心(含快照存储)
- **P4** 各模块批量操作与精修收尾

每期完成后独立可上线;P2–P4 之间无强依赖,顺序可按运营需要调整(①大盘趋势依赖 P3 的快照存储)。

## 8. 验收标准

- 全站(admin/dashboard/sales/auth 页)统一 WhatsApp 风主题,亮/暗切换无残留硬编码色。
- 顶栏中/英切换即时生效,两份字典覆盖全部导航与主要页面文案。
- 四大缺口各有落地页面:实例运维页、风控看板、报表中心、升级版 ProDataTable(批量/列自定义/高级筛选)。
- 后端沿用 testcontainers 真库测试;前端 `npm run build` + eslint 通过(28 条 house-style baseline 不回归)。
